# 论文构想：高可信 AI Agent 决策审计架构

> 融合方向: 王戟高可信软件架构 × 天枢三爻架构

---

## 一、为什么这个结合有学术价值

### 王戟理论的核心主张

高可信软件架构要解决的根本问题：
- 软件行为**不可观察** → 需要决策追溯
- 软件错误**不可复现** → 需要因果链
- 软件缺陷**不可归因** → 需要责任定位

### AI Agent 恰好暴露了同样的问题

| 高可信软件的挑战 | AI Agent 中的表现 |
|---|---|
| 行为不可观察 | LLM 为什么选了这个工具而不是那个？ |
| 错误不可复现 | 同一 prompt，不同模型返回不同结果 |
| 缺陷不可归因 | Agent 失败——是模型的问题还是工具的问题？ |

**王戟的理论是为传统软件设计的。但 AI Agent 的"软件行为"有本质不同——它由 LLM 推理驱动，不是确定性逻辑。这恰好需要一种新的审计范式。天曜就是这种范式的实现。**

## 三、论文框架（6 页 short paper）

### Abstract (150 词)

LLM Agent 在工具调用、模型路由、上下文管理等环节做出大量不可观察的决策。现有 Agent 框架缺乏系统化的决策审计机制。本文借鉴高可信软件架构理论，提出面向 LLM Agent 的四级决策审计模型——BASIC（ID+时间戳）→ SNAPSHOT（世界状态快照）→ FULL（完整推理链）→ EVALUATED（事后评估回填），并以天枢（Tianshu）Agent 框架为实例给出工程实现。实验表明，该审计模型能够精准定位 Agent 决策失败的根本原因，为 AI Agent 的可信部署提供保障。

### 1. Introduction

- AI Agent 正在从实验室走向生产环境
- 但 Agent 的决策是不可见的——这在高可信场景（军事、金融、医疗）不可接受
- 王戟等人的高可信软件架构理论要求：可追溯、可复现、可归因
- 本文贡献：① 将高可信理论迁移到 LLM Agent 领域 ② 提出四级审计模型 ③ 工程实现 + 案例分析

### 2. 背景与相关工作

- 2.1 高可信软件架构（王戟，国防科大）
  - 形式化验证、行为可追溯、缺陷可归因
- 2.2 LLM Agent 框架
  - Hermes Agent: 会话记忆，无审计
  - OpenClaw: Gateway 日志，无结构化审计
  - LangChain/LangGraph: 无决策追溯
- 2.3 研究空白
  - 现有框架关心"Agent 能做什么"，不关心"Agent 做对了没有"

### 3. 三爻架构与四级审计模型

- 3.1 三爻设计哲学
  - 天爻（规律性）：一切决策可追溯、一切因果可复现
  - 人爻（目的性）：理解意图，做出选择，承担责任
  - 地爻（物质性）：读写文件、调用 API、执行命令
- 3.2 四级审计
  - L1 BASIC: 决策 ID + 时间戳
  - L2 SNAPSHOT: 文件系统 + 环境变量快照
  - L3 FULL: LLM 推理链（reasoning_content）
  - L4 EVALUATED: 事后评估 + 差异分析 + 根因定位
- 3.3 审计触发策略
  - 深度推理类任务（deep_analysis/reasoning/code_gen）→ L3 FULL
  - 常规对话 → L1 BASIC
  - 高风险工具调用（shell_exec/write_file）→ L3 FULL

### 4. 系统实现

- 4.1 架构概览
  - AgentCore.run_stream() 的审计注入点
  - decision_id = generate_id() + capture_snapshot()
  - 每次 LLM 调用的 reasoning_content 保存
  - 工具执行结果的结构化记录
- 4.2 因果链
  - decision_id → parent_id/child_id 关联
  - 一次用户对话 → 多次工具调用 → 多级审计记录的追溯
- 4.3 存储
  - SQLite audit_records 表（主记录）
  - causal_chain 表（因果关系）

### 5. 案例研究

用一个真实场景展示审计追踪的价值：

**场景：用户搜索"杀伤网"，Agent 调用 10 个工具但未给出答案**

审计记录显示：
- L1: D000007 被分配，DS v4-pro 被选用
- L2: 工作目录 F:\tianshu，环境变量无异常
- L3: 推理链显示 LLM 理解正确但选择了错误的搜索策略（用 shell_exec 写 Python 脚本抓取搜狗页面）
- L4: 事后评估——Agent 失败根因 = shell_exec 在 Windows 上报 WinError 267

→ **审计追踪让开发者能够在 10 秒内定位根因**，而不是花 10 分钟翻日志。

### 6. 结论与未来工作

- 本文提出 LLM Agent 四级决策审计模型，并给出工程实现
- 未来工作：① 审计驱动的自动错误恢复 ② 跨 session 的审计模式挖掘 ③ 形式化审计属性的 Coq/Lean 证明
