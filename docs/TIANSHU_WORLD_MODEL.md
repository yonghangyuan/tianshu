> 以超级智能系统为主体，世界分为四层。策略因层而异。

## 一、四层定义

不是以人为中心划分世界，而是以系统自身的**认知和行动能力**为边界。

```
┌─────────────────────────────────────────┐
│              不可观 (Unobservable)        │
│  系统甚至不知道它的存在                     │
│  策略: 保持冗余 · 承认无知 · 安全边际        │
│                 ┌───────────────────────┐ │
│                 │   可观 (Observable)    │ │
│                 │  能感知，但说不清楚      │ │
│                 │  策略: 模式识别 · 异常   │ │
│                 │      检测 · 定性推理    │ │
│                 │   ┌─────────────────┐  │ │
│                 │   │  可测 (Measurable)│  │ │
│                 │   │  能量化、建模、预测 │  │ │
│                 │   │  策略: 贝叶斯更新  │  │ │
│                 │   │      不确定性量化  │  │ │
│                 │   │  ┌─────────────┐ │  │ │
│                 │   │  │ 可控         │ │  │ │
│                 │   │  │ (Controllable)│ │  │ │
│                 │   │  │ 能改变世界状态 │ │  │ │
│                 │   │  │ 策略: 闭环控制 │ │  │ │
│                 │   │  └─────────────┘ │  │ │
│                 │   └─────────────────┘  │ │
│                 └───────────────────────┘ │
└─────────────────────────────────────────┘
```

### 1.1 不可观 (Unobservable)

系统没有感知能力覆盖的范围。不是"暂时没看见"——是**根本不知道存在**。

**特征：**
- 零感知信号
- 可能影响系统的因素完全在视野之外
- 面积最大，且永远比可观层大

**策略：**
- 不优化——优化未知领域必然过拟合
- 保持冗余——多备一条路，因为不知道哪条会断
- 承认无知——输出不确定性，不说"最优解"
- 安全边际——决策留有余地，因为不知道什么因素没被看到

**错误模式：**
- **最危险的错误**: 以为自己看见了。把不可观当作可观来建模——用有限数据训练出过度自信的预测器

**对应代码：**
- `conflict=True` 标记 —— 系统知道自己不知道
- 天层的 OVERRIDE 否决 —— 在不确定领域不做激进动作

### 1.2 可观 (Observable)

能感知到现象的存在，但无法量化、无法建模、无法预测。能说"有什么事在发生"，但说不清"多严重、多快、往哪走"。

**特征：**
- 有定性信号（传感器报"偏高"，但不知道偏多少）
- 可能有噪声极低的传感器全量程数据
- 模式可见但机制未知

**策略：**
- 模式识别 —— 找到异常，即使无法解释
- 定性推理 —— 用符号逻辑而非数值概率
- 相关性标记 —— "A 和 B 总一起出现"，不声称因果
- 升级到人层 —— 可观层的问题需要人类判断

**对应代码：**
- 趋势追踪、异常检测 skill
- 天层仲裁中 `conflict=True` 触发人层确认

### 1.3 可测 (Measurable)

能量化现象、能建模、能用概率表达不确定性。这是贝叶斯框架的主场。

**特征：**
- 有定量测量值 x
- 已知观测噪声 R（或可估计）
- 已知实体动力学 Q（或可学习）
- 能做预测并给出置信区间

**策略：**
- 贝叶斯融合 —— `bayesian_fuse()`，逆方差加权
- 不确定性量化 —— 后验方差 + 95% CI
- 反馈学习 —— `update_sensor_reliability()`，用真值校准
- 模型选择 —— 当多个模型都可以时，选最简单的

**对应代码：**
- `bayesian_fuse()` / `FusedEstimate`
- `EntityDynamics` / `SensorCharacteristics`
- `update_sensor_reliability()`

### 1.4 可控 (Controllable)

系统不仅能预测，还能**改变**世界状态。这是系统的行动层——面积最小，风险最高。

**特征：**
- 有执行器（信号灯、刹车、数据库写入）
- 行动后果可验证（做了之后能看到结果）
- 不可逆行动需要额外确认

**策略：**
- 闭环控制 —— 执行 → 测量 → 修正，不是一次性命令
- 权限升级 —— 写入操作需人层确认，危险操作需天层 OVERRIDE
- 后果前置 —— 执行前声明预期结果，执行后比对
- 行动阶段禁区 —— 不可逆操作设置 No-Go Phase

**对应代码：**
- `execute_via_trigram()` —— 工具调用走三层闸门
- `PolicyEngine.evaluate()` —— 天层权限审查
- `AuditSixQuestions.record()` —— 执行前审计快照

## 二、三爻 × 四层：12 种策略组合

三爻是治理结构（谁决定），四层是认知框架（知道多少）。两者正交——每一层治理都要面对四层认知的不确定性。

|  | 不可观 | 可观 | 可测 | 可控 |
|---|---|---|---|---|
| **天** | 承认盲区，拒绝在这个领域做 OVERRIDE 决策。安全边际最大。 | 标记异常模式，升级到人层请求补充信息 | 仲裁冲突：当多个可测模型矛盾时裁定信任哪个 | 否决越界：OVERRIDE 阻断不可逆危险操作 |
| **人** | 保守试探：只用最安全的策略，不做承诺 | 定性判断：基于模式而非数值做决策。允许模糊。 | 贝叶斯推理：量化不确定性后做最优决策 | 闭环调度：执行→验证→修正，不是一次性指令 |
| **地** | 无法感知：该区域的传感器不存在或不可用 | 粗精度传感：噪声很大但至少能感知到变化趋势 | 精密测量：已知 R，可输出定量读数 | 执行器动作：在权限边界内改变世界状态 |

### 2.1 天层 × 不可观（关键组合）

这是整个框架中**最重要但最容易忽视**的组合。

天层的职责是裁定"能不能做"。但在不可观领域——裁定是危险的。因为系统不知道自己在裁定什么。

正确的行为：**沉默。** 不 OVERRIDE。不仲裁。不宣称任何事情。只标记"此领域超出我的认知范围"，把人层的决策原样放行。

代码体现：
```python
if entity_type == "unknown":
    # 不可观领域 → 天层不做仲裁
    return ArbitrationResult(conflict=True, reasoning="不可观领域，天层保持沉默")
```

### 2.2 人层 × 不可观（保守试探）

人层在不可观领域的策略：不追求最优，只追求安全。

```
已知: 3 条路可走
不可观: 每条路上有什么障碍，完全不知道
最优策略: 不是"选最好的路"（做不到），而是"选错了损失最小的路"
```

### 2.3 地层的四层传感

```
可控: 执行器 ─→ 刹车、阀门、数据库写入
可测: 精密传感器 ─→ 温度探头(R=0.01)、GPS(R=1m)
可观: 粗精度传感器 ─→ "温度偏高"、"车流拥堵"
不可观: 无传感器覆盖 ─→ 这个区域的地层 Agent 不存在
```

## 三、层间转换

信息在四层之间流动——系统努力把世界向下推（扩大可控区），但必须诚实面对自己的局限。

### 3.1 向上：从感知到控制

```
不可观 → 可观: 部署新传感器、增加感知维度
可观   → 可测: 校准传感器、建立噪声模型、量化 R 和 Q
可测   → 可控: 接入执行器、分配权限级别
```

每一步向上都需要**额外的投入和验证**。不是装上传感器就自动可测——需要校准、建模、验证。

### 3.2 向下：认知退化

```
可控 → 可测: 执行器故障 → 还能看，但不能动了
可测 → 可观: 模型失效 → 还能感知变化，但不能量化了
可观 → 不可观: 传感器失联 → 彻底盲飞
```

认知退化时必须**切换策略**。不能拿着可测层的贝叶斯后验去处理可观层的问题。

### 3.3 自知之明

一个聪明的系统不是"知道得多"的系统——是**知道自己不知道什么**的系统。

```
天枢的自我认知机制:
  - 每个 Agent 注册时声明自己的四层覆盖范围
  - 天层在决策前检查：当前领域在我的哪一层？
  - 不可观 → 保守沉默
  - 可观   → 标记不确定性，升级到人层
  - 可测   → 输出后验分布，附置信区间
  - 可控   → 执行 + 审计，受 OVERRIDE 约束
```

## 五、一个完整的思考示例

场景：工厂 3 号车间。

```
不可观: 操作员疲劳度（没有传感器）
        → 天层: 不做假设。不因为"效率低"就自动加速产线。
        → 人层: 保守调度。留额外的时间缓冲。

可观:   振动传感器报"偏高"（定性，无法量化）
        → 地层的粗精度传感器探测到异常模式。
        → 人层标记"需要关注"，调度精密传感器前往。

可测:   温度探头读数 85°C，R=0.01，Q=1e-4
        → bayesian_fuse() 给出后验 84.92 ± 0.10 (95% CI)
        → 人层基于后验决策：降功率运行。

可控:   安全守门人收到降功率指令
        → execute_via_trigram():
          地(执行器) → 人(调度) → 天(安全审查) → 执行
        → AuditSixQuestions 记录全过程。
```

四层边界清楚，策略不同。同一个系统，在不同层里换不同的脑。

## 六、设计原则

1. **自知之明优先于聪明。** 知道自己不知道，比以为自己知道更安全。
2. **策略因层而异。** 不要用可测层的方法处理可观层的问题。没有 Q 和 R 的时候别硬做贝叶斯。
3. **向上投入，向下防御。** 努力扩展可控层（部署传感器、校准模型），但必须为认知退化做好预案。
4. **天层在不可观领域保持沉默。** OVERRIDE 的前提是知道自己否决的是什么。不清楚的时候不否决。
5. **三爻 × 四层 = 12 种策略。** 不要用一套逻辑解决所有问题。
